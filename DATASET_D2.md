# D2 — the capturing-atom selector and the atomic-capture reference corpus

## The selector

Geant4 chooses the element whose nucleus takes a stopped negative muon in `G4ElementSelector::SelectZandA`, weighting each element of the material by its atomic number times its atom number density, with a reduced factor for the halogens and for oxygen. The weighting runs only when the material holds more than a single element, and the same function then draws the isotope from the element's relative abundances. `G4HadronStoppingProcess::AtRestDoIt` calls the selector before the capture cascade runs, and `G4MuonMinusAtomicCapture` calls it on the muonic-atom route. The stopping constructors register process classes derived from `G4HadronStoppingProcess` for the negative muon, pion and kaon and for the antiproton, so the same selector picks the capturing element for each of them. `SelectZandA` contains no step that moves the muon from the element it picks to another, so the element it picks is the element whose nucleus the capture code then uses. A review of muon capture explains that a muon captured by hydrogen forms a neutral system that can pass to a heavier nucleus nearby, and calls polyethylene effectively a carbon target and water a convenient oxygen target.

## The reference corpus

`selector_harvest.csv` records, for each material the harness `cpp/tools/harvest_d2.cc` builds, the element that each draw of a fixed ladder of uniform draws selects in a compiled Geant4 library, and `openmucf/g4/d2.py` reproduces every count from the harvested atom number densities. `harvest_builds.csv` names the Geant4 builds, `selector_bindings.csv` lists the process each of these particles meets at rest in each reference physics list the harness builds, and `selector_call_sites.csv` lists the calls of the selector and the classes derived from `G4HadronStoppingProcess` in each Geant4 source tree. `reference/d2/sources.csv` lists each publication this corpus considered, the route by which it was reached and whether a copy was read. `printed_rows.csv` transcribes the measured values those copies print, row by row as printed, and `measurements.csv` restates each with the method and corrections its source states. Of a caption, `printed_rows.csv` keeps the table's title; of a note or footnote of more than a sentence, only its footnote marker, if any; in place of the text it leaves out, it gives the SHA-256 of that text, and `measurements.csv` cites such a footnote by its locator. Where a source states its capture-branch correction, `measurements.csv` gives the SHA-256 of the source's words in place of them, before the page that states it. A per-atom capture ratio divides the fraction of muons captured by an element, per atom of that element in the target, by the same quantity for another element. A primary in this corpus contrasts the muonic X-ray and decay-electron lifetime methods: for muonic X-ray intensities the energy dependence of the detector's efficiency is a serious problem, and for decay-electron lifetimes the main correction is for muon absorption, which reduces the number of decay electrons. `selector_vs_primary.csv` sets beside each measurement row whose `inferable_parameter` is a per-atom ratio `A(X/Y)` the ratio the selector's weights give for the same pair of elements, and marks a row as gated only when it measures the element that finally takes the muon among all muons stopped in the target, prints an uncertainty, and its source states the method and the corrections behind the ratio. Nothing in these files changes how Geant4 picks the capturing element.

The `method_gated`, `method_reason` and `method_result` columns repeat that gating and comparison under a second rule, which was adopted after the selector's ratio had already been compared with the rows it gates. The second rule asks a row's source only for the corrections its measurement method involves: for a decay-electron lifetime measurement the detection efficiency, the attenuation and the correction recorded in the `capture_branch_correction` column of `measurements.csv` for muons absorbed by the nucleus, which give no decay electron, and for the bound muon's reduced decay probability; for a muonic X-ray measurement the detection efficiency, the attenuation and the cascade; and all of these for a method recorded as `other`. It does not ask for a transfer correction, because both rules admit only rows that count the element that finally takes the muon among all muons stopped in the target. Every row the second rule gates lies `outside` in `method_result`. `selector_summary.csv`, generated from `selector_vs_primary.csv`, describes those rows: there are 63, each a per-atom ratio of an element to oxygen; 62 are in the class `d2-selector-oxides` and 1, of calcium hydroxide, in the class `d2-selector-other-compounds`. On each of them the selector's ratio lies above the measured ratio, at between 1.59 and 5.70 times the measured ratio and at 2.96 times it at the median, and the ratio of the atomic numbers of the pair, which the selector's weights give without the reduced factor for oxygen, lies closer to the measured ratio on 63 of them. That factor raises the selector's ratio on every row: on 58 the ratio of the atomic numbers already lies above the measured ratio, and on the other 5 the factor carries the selector's ratio past it. Of those rows, 1, the calcium hydroxide row, is of a material that holds hydrogen, in which, as the review cited in the first section explains, a muon captured by hydrogen forms a neutral system that can pass to a heavier nucleus nearby; since `SelectZandA` has no step that moves a muon between elements, for that row the difference may come from such transfer rather than from the weights, and this comparison does not tell them apart. For the 62 rows whose material holds no hydrogen, the comparison tests the selector as Geant4's model of the element that finally takes the muon, the element whose nucleus the capture code then uses; it does not tell whether the difference arises in the weights or in the steps by which the muon reaches that element. The `screen` column applies the comparison of the `result` column to every row that carries a selector ratio and a printed uncertainty, gated or not, reading an uncertainty printed in parentheses as a count of units in the last digit printed in the value; for a row that neither rule gates it describes a difference and does not test the selector.

## Measured vectors behind an opt-in selector

`data/g4/d2/measured/` carries, for each oxide row of the decay-electron lifetime measurement in `measurements.csv`, a table of the probability that a stopped negative muon ends on each element of the nominal hydrogen-free solid, formed from the per-atom ratio the source reports, and `evaluation.json` records the precision and improvement decisions taken against each vector. `docs/measured-oxide-capture.md`, generated from the evaluation, states the transform, the decisions and what they do not establish. `cpp/material_selector/` holds a provider that Geant4 reads these tables through, only for a material a caller binds to a table explicitly; without a binding, and when the provider is not registered, the selector described in the first section runs unchanged. `cpp/material_selector/README.md` describes the provider, its binding rules and the checks run against Geant4 builds.

## Building the harvest

The harvest is built and run against each Geant4 install as follows:

```sh
g++ -std=c++17 -O2 -ffp-contract=off cpp/tools/harvest_d2.cc -o harvest_d2 $(<install>/bin/geant4-config --cflags --libs)
env -i PATH=/usr/bin:/bin HOME=$HOME LD_LIBRARY_PATH=<install>/lib GEANT4_DATA_DIR=<data> ./harvest_d2 selector > selector.txt
env -i PATH=/usr/bin:/bin HOME=$HOME LD_LIBRARY_PATH=<install>/lib GEANT4_DATA_DIR=<data> ./harvest_d2 bindings <physics list> > bindings.txt
```
